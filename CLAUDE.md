# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

sashimi (PyPI distribution **`sashimi-convert`**, import name `sashimi`) is a Python ≥3.11 library for file conversion and video contact sheets, built on FFmpeg/ffprobe (system binaries on `PATH`) and Pillow. It is the conversion engine behind FileSushi's sandboxed workers and the basis of a desktop app, and ships a Typer CLI (`sashimi`, entry point `sashimi.cli:main`, needs the `[cli]` extra). Uses `uv`; hatchling (≥1.27, for PEP 639 licence metadata; both targets pinned to core metadata 2.4) builds; the version lives only in `src/sashimi/_version.py`, and the first `## ` heading of `CHANGELOG.md` must match it (`tests/test_metadata.py`). `CHANGELOG.md` must record every Python API break (pre-1.0, breaks are allowed), with upgrade steps in `MIGRATION.md`; `docs/FILESUSHI_HANDBACK.md` documents the contract FileSushi depends on, and `tests/core/test_filesushi_contract.py` pins the parts of it that aren't field definitions. `CLAUDE.md` and the handback stay out of the sdist (`[tool.hatch.build.targets.sdist]`) and the wheel. The owner builds and uploads releases by hand; never publish, tag or add a publishing workflow.

Licensing: Apache-2.0, copyright "The FileSushi Authors" (listed in `AUTHORS`). Every hand-written source file (`.py`, `.sh`, `pyproject.toml`, the sandbox `Dockerfile`) starts with the two lines `# SPDX-FileCopyrightText: 2026 The FileSushi Authors` / `# SPDX-License-Identifier: Apache-2.0` (after a shebang if there is one); `tests/test_licensing.py` fails on a tracked or new file without them. Keep `LICENSE` verbatim; there is no `NOTICE`.

## Commands

```sh
sh scripts/check.sh                 # ruff format --check, ruff check, mypy, pytest on 3.11–3.14; run before handing work back (there is no CI)
uv run pytest tests/core/test_video_commands.py::test_gif_defaults    # single test
uv run pytest tests/core            # fast unit tests, no ffmpeg needed
sh scripts/sandbox_check.sh [--skip-long]   # every converter in a FileSushi-style locked-down Alpine container (needs Docker)
uv run sashimi thumbs <path> -r     # run the CLI
```

`check.sh` changes nothing: `uv run --frozen` (never re-locks) with `UV_PROJECT_ENVIRONMENT=.venvs/<version>` (override the parent with `SASHIMI_CHECK_VENVS`), so `.venv` and `uv.lock` are left alone. Ruff line length is 120; `F401` is ignored. Integration tests (`tests/integration`, some `tests/cli`) generate media at test time with lavfi `testsrc2`/`sine` (fixtures in `tests/conftest.py`, inputs named `original.blob`) and skip without ffmpeg. `tests/conftest.py` silences Pillow's DEBUG logger: with pyproject's `log_cli` at DEBUG, log records inside typer's `CliRunner` close its captured output on Python 3.11.

## Architecture: three layers

1. **Core** (`sashimi/core/`, re-exported by the public faces `sashimi.video`, `.audio`, `.image`, `.sheets`, and `sashimi.probe`/`sashimi.errors`). Single-file functions `(input_path, output_path, config, *, max_workers, scratch_dir, on_progress)`; `image.convert`, `image.to_ico` and `image.favicon_pack` take `max_pixels` instead of `max_workers`, and `sheets.render` adds `display_name`, `header_font`, `timestamp_font` and `emoji_dir`. Hard rules, because FileSushi runs them in a read-only, no-network, `pids_limit=128` container:
   - never derive outputs from inputs, `.resolve()`, or look at extensions; detect input type by content (`core/probe.py` via ffprobe JSON, or Pillow) and take output format from the config (`-f <muxer>`);
   - write via `core/_atomic.atomic_output` only; pipe frames (raw RGB over stdout/stdin) instead of temp files;
   - no config files or network, and nothing written under `HOME` (pilmoji emoji only from a local `emoji_dir`). One read under `HOME` remains: without `header_font`/`timestamp_font`, sheets try system font names (`core/sheets/_render._FONT_CANDIDATES`), and Pillow's `ImageFont.truetype` also searches per-user font folders (`~/.local/share/fonts`, `~/Library/Fonts`), so sheet text depends on the host's fonts; pass font paths for repeatable output;
   - bound threads: `core/_resources.resolve_max_workers` (default `min(4, CPUs)` honouring cgroup quotas); every ffmpeg call gets `-filter_threads` through `base_args()`, and every decode and encode gets `-threads`. The exceptions: ffprobe gets neither; copy trims and remuxes (no decode or encode, `base_args(1)`), the animated-GIF sheet encode and the preview's GIF encode get no `-threads`;
   - raise `UserInputError` subclasses (with a plain-sentence `.user_message`) for user-fixable problems and `ProcessingError` otherwise; callers branch on type, never message text. Code that turns a `ProcessingError` into a user error or a skipped frame (`probe()`, the sheet frame grabs) must re-raise `BinaryNotFoundError` first, so a missing ffmpeg/ffprobe is never reported as bad media.
   All ffmpeg runs go through `core/_ffmpeg.run_ffmpeg` (progress parsing, stdin feeding, stderr tail). Command builders (`build_*_command`) are **pure** and pinned argument-for-argument by parity tests (`tests/core/test_*_commands.py`); changing an argument is a FileSushi-visible change. Every output gets `OUTPUT_FLAGS` (`-fflags +bitexact`) so results are byte-identical; inputs get `INPUT_PROTOCOLS` (`-protocol_whitelist file -format_whitelist <VIDEO_CONTAINERS | AUDIO_CONTAINERS>`, both sets defined in `core/_ffmpeg.py`) and must pass the container allowlists re-exported by `core/probe.py`. Every re-encode gets `-t`: the requested length, or the probed remainder plus `DURATION_TOLERANCE_SECONDS`, capped at the limit. Outputs come from `atomic_output` with mode 0666 minus the umask.
   Config models live in `sashimi/config/` (FileSushi's web app imports it, so it may import only pydantic and `sashimi.errors`; `tests/core/test_config_module.py` pins that). One model per operation and output format, holding only fields that affect that output, with concrete defaults (`None` only for "keep the source's value"/"to the end"); limits that don't depend on the file are field bounds, with friendly text in `bound_messages`, and cross-field rules raise `sentence(...)`. Models subclass `ParamsModel` (frozen, `extra="forbid"`, `use_attribute_docstrings`, `None` → default, `from_params(params, **fields)` → `InvalidOptionsError`); every field needs a user-facing docstring right under it, which becomes its `description` (FileSushi form help, `sashimi config defaults`; `test_every_field_is_described` pins it); each operation's `ConfigFamily` (`IMAGE_CONVERT`, `VIDEO_TRIM`, `CONTACT_SHEET`, …) picks the model. Field names match FileSushi's form fields; server paths (fonts, `emoji_dir`) are function arguments, never fields.
   Contact sheets: `core/sheets/__init__.render` dispatches to `static.py` (frames via a thread pool of single-threaded ffmpeg) or `animated.py` (clips decoded to raw frames, composited with Pillow, encoded by one ffmpeg; no moviepy); `_layout.py` is pure grid/timestamp maths plus the tile-size check, `_render.py` draws header/labels with local fonts.
2. **Batch API** (`sashimi/api/`, lazy `__getattr__` exports). `_batch.run_batch` does discovery by extension, plans every output name before writing anything, handles `exists`/`force`, and maps exceptions to statuses by type (`classify`). The output-naming policy is in the `_batch` module docstring and the README ("Where outputs go"), and the owner accepted it on 2026-10-20: conversions are `<stem>.<ext>`; derived outputs are `<stem>.<role>.<ext>` (`.sheet`, `.animated-sheet`, `.preview`, `.resized`, `.rotated`, `.extracted`, `.favicons.zip`); outputs go next to inputs, under `output_dir`, or to `output` for one input; colliding names keep their input extension (`a.png.webp`), compared case-insensitively; an output never replaces one of the batch's inputs; an existing output is `exists` unless `force`, which replaces it and says so. Every new batch function follows it. Generators yield: file count, then rejected inputs, then per file `(path, "starting", message, output)` followed by `(path, status, message, output)` with status `success | error | exists | skipped` (`ResultTuple`). `_consume.consume_generator` turns that into a summary dict (optional tqdm).
3. **CLI** (`sashimi/cli/`). `main.py` builds the Typer app (`--version`, help panels, `no_args_is_help` on every command that takes arguments) and registers `convert`, `resize`, `rotate`, `favicon`, `extract` (hidden alias `trim`), `remux`, `thumbs`, `preview`, `info`, `flatten` and `config`, from `convert_cmd.py`, `thumbs_cmd.py`, `files_cmd.py` and `config_cmd.py`. Every processing command prints the same `--json` report (`schema`, `command`, `summary`, `results`); `info` and `config` keep their own JSON shapes. All logging goes to stderr. `-o/--output` is always the output file, `--format` (no short flag) the format, `--duration` an output length and `--clip-length` a sampled clip's length; `-h` is help everywhere. Shared option declarations live in `_options.py` (one `Annotated` alias per flag, grouped into help panels), and `_output.BatchRunner` renders batch progress (including per-file progress via `on_file_progress`) and results/JSON. Commands import heavy modules inside the function body so `--help` stays ~0.2 s; keep it that way. When adding a config field, expose it as a flag too, add it to the command's `FLAGS` map, and give the flag a `[default: …]` note matching the model; `tests/cli/test_help_defaults.py` checks every note against the model defaults. Declare options with `_options.option(...)`, which escapes `[default:` (Rich would otherwise read it as a markup tag and delete it); a bare `typer.Option` help must not contain `[default:` or other lowercase `[...]`. `_defaults.py` formats defaults, accepted values and `sashimi.toml` overrides for `sashimi config defaults <command> [format]` and for `thumbs --help` (`thumbs_cmd.ThumbsCommand` annotates help with TOML values at render time; `settings.read_config()`). `settings.py` is the only code that reads/writes TOML (`~/.sashimi/sashimi.toml`, project `sashimi.toml`; the only sections are `[thumbs]` and `[animated_thumbs]`, since the dead `[global]` settings were removed in 0.6.0); only `sashimi config set` creates or writes a file, never a normal run, and built-in sheet defaults come from the models, not a TOML template (a written template pins old defaults). `settings.known_keys` is the one list of keys each section accepts: `config set` refuses others, and `load_raw_config` warns once per run about any in a file (help stays silent). It also maps 0.2-era keys (`static_width`, `jpeg_quality`, `animated_width`, `output_format`, `output_fps`) onto core field names, and turns the path keys (`header_font_path`, `timestamp_font_path`, `emoji_dir`) into `sheets.render` arguments. Flags a chosen model doesn't have are dropped with a warning (`_options.split_options`, `_output.warn_unused`).

## Dependencies

Core: `pydantic`, `pillow` only. Extras: `[cli]` typer/rich/tomlkit, `[emoji]` pilmoji, `[heif]` pillow-heif. FileSushi workers are `python:3.14-alpine` (musl) and install wheels only (`--only-binary=:all:`): ask Rio before adding any dependency without musllinux wheels or that compiles from source, and before changing how outputs look.

## Owner decisions that shape new work

- **sashimi powers FileSushi Desktop,** so any behaviour FileSushi or the desktop app should share belongs here, not in FileSushi's worker (owner, 2026-10-20).
- **One operation per thing the user wants; sashimi picks the route.** For example, converting to MP4 should stream-copy when the codecs allow and re-encode otherwise, without the caller choosing. Don't expose implementation routes as separate tools or options (owner, 2026-10-20).
- **Not wanted:** a two-input mux (ftool's `--merge-split`), and anything that deletes a source file (ftool's `--cleanup`) (owner, 2026-10-20).
- **The first PyPI release is 0.6.0,** and it waits for image editing (crop, rotate, flip, adjust, and frame selection for animated images) (owner, 2026-10-20).
