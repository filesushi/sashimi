# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

sashimi (PyPI distribution **`sashimi-convert`**, import name `sashimi`) is a Python ≥3.11 library for file conversion and video contact sheets, built on FFmpeg/ffprobe (system binaries on `PATH`) and Pillow. It is the conversion engine behind FileSushi's sandboxed workers and the basis of a desktop app, and ships a Typer CLI (`sashimi`, entry point `sashimi.cli:main`, needs the `[cli]` extra). Uses `uv`; hatchling builds; the version lives only in `src/sashimi/_version.py`. `CHANGELOG.md` must record every Python API break (pre-1.0, breaks are allowed); `docs/FILESUSHI_HANDBACK.md` documents the contract FileSushi depends on.

## Commands

```sh
sh scripts/check.sh                 # ruff format, ruff check, mypy, pytest on 3.11–3.14 (the CI gate)
uv run pytest tests/core/test_video_commands.py::test_gif_defaults    # single test
uv run pytest tests/core            # fast unit tests, no ffmpeg needed
sh scripts/sandbox_check.sh [--skip-long]   # every converter in a FileSushi-style locked-down Alpine container (needs Docker)
uv run sashimi thumbs <path> -r     # run the CLI
```

Ruff line length is 120; `F401` is ignored. Integration tests (`tests/integration`, some `tests/cli`) generate media at test time with lavfi `testsrc2`/`sine` (fixtures in `tests/conftest.py`, inputs named `original.blob`) and skip without ffmpeg. `tests/conftest.py` silences Pillow's DEBUG logger: with pyproject's `log_cli` at DEBUG, log records inside typer's `CliRunner` close its captured output on Python 3.11.

## Architecture: three layers

1. **Core** (`sashimi/core/`, re-exported by the public faces `sashimi.video`, `.audio`, `.image`, `.sheets`, and `sashimi.probe`/`sashimi.errors`). Single-file functions `(input_path, output_path, config, *, max_workers, scratch_dir, on_progress)`. Hard rules, because FileSushi runs them in a read-only, no-network, `pids_limit=128` container:
   - never derive outputs from inputs, `.resolve()`, or look at extensions; detect input type by content (`core/probe.py` via ffprobe JSON, or Pillow) and take output format from the config (`-f <muxer>`);
   - write via `core/_atomic.atomic_output` only; pipe frames (raw RGB over stdout/stdin) instead of temp files;
   - no config files, `HOME` or network (pilmoji emoji only from a local `emoji_dir`);
   - bound threads: `core/_resources.resolve_max_workers` (default `min(4, CPUs)` honouring cgroup quotas) and `-threads`/`-filter_threads` on every ffmpeg call;
   - raise `UserInputError` subclasses (with a plain-sentence `.user_message`) for user-fixable problems and `ProcessingError` otherwise; callers branch on type, never message text.
   All ffmpeg runs go through `core/_ffmpeg.run_ffmpeg` (progress parsing, stdin feeding, stderr tail). Command builders (`build_*_command`) are **pure** and pinned argument-for-argument by parity tests (`tests/core/test_*_commands.py`); changing an argument is a FileSushi-visible change. Every output gets `OUTPUT_FLAGS` (`-fflags +bitexact`) so results are byte-identical; inputs get `INPUT_PROTOCOLS` (`-protocol_whitelist file -format_whitelist <VIDEO_CONTAINERS | AUDIO_CONTAINERS>`, both sets defined in `core/_ffmpeg.py`) and must pass the container allowlists re-exported by `core/probe.py`. Every re-encode gets `-t`: the requested length, or the probed remainder plus `DURATION_TOLERANCE_SECONDS`, capped at the limit. Outputs come from `atomic_output` with mode 0666 minus the umask.
   Config models live in `sashimi/config/` (FileSushi's web app imports it, so it may import only pydantic and `sashimi.errors`; `tests/core/test_config_module.py` pins that). One model per operation and output format, holding only fields that affect that output, with concrete defaults (`None` only for "keep the source's value"/"to the end"); limits that don't depend on the file are field bounds, with friendly text in `bound_messages`, and cross-field rules raise `sentence(...)`. Models subclass `ParamsModel` (frozen, `extra="forbid"`, `use_attribute_docstrings`, `None` → default, `from_params(params, **fields)` → `InvalidOptionsError`); every field needs a user-facing docstring right under it, which becomes its `description` (FileSushi form help, `sashimi config defaults`; `test_every_field_is_described` pins it); each operation's `ConfigFamily` (`IMAGE_CONVERT`, `VIDEO_TRIM`, `CONTACT_SHEET`, …) picks the model. Field names match FileSushi's form fields; server paths (fonts, `emoji_dir`) are function arguments, never fields.
   Contact sheets: `core/sheets/__init__.render` dispatches to `static.py` (frames via a thread pool of single-threaded ffmpeg) or `animated.py` (clips decoded to raw frames, composited with Pillow, encoded by one ffmpeg; no moviepy); `_layout.py` is pure grid/timestamp maths plus the tile-size check, `_render.py` draws header/labels with local fonts.
2. **Batch API** (`sashimi/api/`, lazy `__getattr__` exports). `_batch.run_batch` does discovery by extension, "output next to input", `exists`/`force`, and maps exceptions to statuses by type (`classify`). Generators yield: file count, then rejected inputs, then per file `(path, "starting", …)` followed by `success | error | exists | skipped`. `_consume.consume_generator` turns that into a summary dict (optional tqdm).
3. **CLI** (`sashimi/cli/`). `main.py` builds the Typer app (`--version`, help panels, `no_args_is_help` on every command that takes arguments) and registers commands from `convert_cmd.py` (convert/resize/rotate), `thumbs_cmd.py`, `files_cmd.py` (extract/trim, flatten, info) and `config_cmd.py`. Shared option declarations live in `_options.py` (one `Annotated` alias per flag, grouped into help panels), and `_output.BatchRunner` renders batch progress (including per-file progress via `on_file_progress`) and results/JSON. Commands import heavy modules inside the function body so `--help` stays ~0.2 s; keep it that way. When adding a config field, expose it as a flag too, add it to the command's `FLAGS` map, and give the flag a `[default: …]` note matching the model; `tests/cli/test_help_defaults.py` checks every note against the model defaults. Declare options with `_options.option(...)`, which escapes `[default:` (Rich would otherwise read it as a markup tag and delete it); a bare `typer.Option` help must not contain `[default:` or other lowercase `[...]`. `_defaults.py` formats defaults, accepted values and `sashimi.toml` overrides for `sashimi config defaults <command> [format]` and for `thumbs --help` (`thumbs_cmd.ThumbsCommand` annotates help with TOML values at render time; `settings.read_config()`). `settings.py` is the only code that reads/writes TOML (`~/.sashimi/sashimi.toml`, project `sashimi.toml`); only `sashimi config set` creates or writes a file, never a normal run, and built-in sheet defaults come from the models, not a TOML template (a written template pins old defaults). `settings.known_keys` is the one list of keys each section accepts: `config set` refuses others, and `load_raw_config` warns once per run about any in a file (help stays silent). It also maps 0.2-era keys (`static_width`, `jpeg_quality`, `animated_width`, `output_format`, `output_fps`) onto core field names, and turns the path keys (`header_font_path`, `timestamp_font_path`, `emoji_dir`) into `sheets.render` arguments. Flags a chosen model doesn't have are dropped with a warning (`_options.split_options`, `_output.warn_unused`).

## Dependencies

Core: `pydantic`, `pillow` only. Extras: `[cli]` typer/rich/tomlkit, `[emoji]` pilmoji, `[heif]` pillow-heif. FileSushi workers are `python:3.14-alpine` (musl) and install wheels only (`--only-binary=:all:`): ask Rio before adding any dependency without musllinux wheels or that compiles from source, and before changing how outputs look.
